# Регламент тестирования (tests/GEMINI.md)

Данные правила применяются при написании, рефакторинге и запуске тестов в директории `tests/`.

---

## 1. Стек и инфраструктура тестов

* **Фреймворк**: `pytest`, `pytest-asyncio` для асинхронных тестов (`@pytest.mark.asyncio` или async fixtures).
* **HTTP клиент**: `httpx.AsyncClient` с `ASGITransport(app=app)`.
* **База данных**: Изолированная in-memory SQLite (`sqlite+aiosqlite:///:memory:`) с пулом `StaticPool`, управляемая через фикстуры `setup_test_db` и `db_session` в [tests/conftest.py](file:///c:/Projects/getbalanceai_api/tests/conftest.py).
* **Мокирование Redis**: Использование `fakeredis.aioredis.FakeRedis` во избежание зависимости от внешнего сервера Redis.
* **Мокирование внешних LLM (Gemini)**: Изолировать вызовы через `unittest.mock.patch` или фиктивные клиенты, не совершать реальных сетевых запросов в тестах.

---

## 2. Стандарты написания тестов

* **Принцип независимости (Isolation)**:
  * Каждый тест должен быть полностью автономен. Запрещено полагаться на порядок выполнения тестов или состояние, оставленное предыдущим тестом.
  * Все тестовые данные должны создаваться внутри теста или фикстур.
* **Обязательные сценарии покрытия**:
  * **Happy Path**: Успешное выполнение с проверкой структуры данных и статус-кодов (200, 201, 204).
  * **Валидация (422)**: Некорректные типы, выходящие за лимиты значения, пустые поля.
  * **Безопасность и Auth (401, 403)**: Доступ без токена, с просроченным токеном, попытка доступа к чужим ресурсам (`user_id` mismatch).
  * **Ошибки бизнес-логики (400, 404, 409)**: Несуществующие сущности, дубликаты, превышения лимитов.
* **Соответствие контрактам API**:
  * Ответы эндпоинтов проверять на соответствие `ApiResponse[T]` (`{"status": "success", "data": ...}`) либо `ErrorResponse` (`{"status": "error", "error": {"code": ..., "message": ...}}`).

---

## 3. Запреты и ограничения

* Запрещено сохранять временные файлы баз данных на диск в корень проекта.
* Запрещено оставлять закомментированные тесты, неинформативные ассерты (`assert True`) или пустые заглушки.
* Не оставлять отладочные `print()` — для отладки использовать флаг `pytest -s` при необходимости, но удалять принты перед коммитом.

---

## 4. Команды для пользователя

* **Агент не запускает тесты автоматически перед пушем/коммитом**: запуск тестов выполняется пользователем либо хуками репозитория.
* При добавлении или изменении тестов агент информирует пользователя и предоставляет команду для ручного запуска:

```bash
# Запуск полного набора тестов
pytest tests/ -v

# Запуск конкретного тестового файла
pytest tests/test_<module_name>.py -v
```
