# Реализация задач

Правила (ветки, запрет запуска линтеров/pytest/alembic/docker, ревью, документация, git, клиенты) — в корневом `CLAUDE.md`; он уже в контексте, не перечитывать. Здесь только порядок.

1. **План и ветка**: сгруппировать задачи по модулю/слою, план — 2–5 строк; при чистом `git status` ветка `<feat|fix|refactor>/<topic>` от `main`.
2. **Реализация**: читать и править только целевые файлы; слои, `ApiResponse[T]`, ошибки через наследников `AppException`, тайп-хинты, docstrings, логирование.
3. **Тесты**: unit/интеграционные на изменённое поведение — happy path и негатив (валидация, 401/403/404, невалидные токены).
4. **Миграции и доки**: миграция без применения; в README/ARCHITECTURE/RESPONSE_FORMAT/TEST_CHECKLIST — только разделы, которые задевает дифф.
5. **Итог**: ревью по `git diff`, блок команд из `CLAUDE.md`, изменения контрактов API. Без `git commit`.
