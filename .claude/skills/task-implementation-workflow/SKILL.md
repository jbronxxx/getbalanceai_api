# Реализация задач

Правила (ветки, проверки, ревью, документация, git, клиенты) — в корневом `CLAUDE.md`; он уже в контексте, не перечитывать. Здесь только порядок.

1. **План и ветка**: сгруппировать задачи по модулю/слою, план — 2–5 строк; при чистом `git status` ветка `<feat|fix|refactor>/<topic>` от `main`.
2. **Реализация**: читать и править только целевые файлы; слои, `ApiResponse[T]`, ошибки через наследников `AppException`, тайп-хинты, docstrings, логирование. Повторы — в общий помощник; ставший неиспользуемым код — удалить вместе с тестами.
3. **Тесты**: unit/интеграционные на изменённое поведение — happy path и негатив (валидация, 401/403/404, невалидные токены).
4. **Миграции и доки**: миграция, проверенная на локальной базе (upgrade → downgrade → upgrade → `alembic check`); в README/ARCHITECTURE/RESPONSE_FORMAT/TEST_CHECKLIST — только разделы, которые задевает дифф.
5. **Проверки**: black/isort/flake8, pytest на SQLite и на временной базе Postgres, при изменении API — запросы к живому API в докере (скилл `getbalance-local-backend`).
6. **Итог**: ревью по `git diff`, фактические результаты проверок, изменения контрактов API. Без `git commit`.
