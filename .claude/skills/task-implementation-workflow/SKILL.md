# Реализация задач

Общие правила (ветки, запрет запуска линтеров/pytest/alembic/docker, ревью, документация, git-гигиена, клиенты) — в корневом `CLAUDE.md`; здесь только порядок действий.

1. **План**: изучить требования, сгруппировать связанные задачи (модуль/домен/слой), кратко зафиксировать план.
2. **Ветка**: `git status` должен быть чистым; `git checkout -b <feat|fix|refactor>/<topic> main`. Работа только через ветки и PR (хук `no-commit-to-branch`).
3. **Реализация**: править только целевые файлы; Layered Architecture, единый формат ответов, ошибки через `AppException`-наследники; тайп-хинты, docstrings, логирование.
4. **Тесты**: недостающие unit/интеграционные, включая негатив и граничные случаи (валидация, недоступность БД, невалидные токены).
5. **Инфраструктура/доки**: миграция (не применять) → `alembic upgrade head`; зависимости/Docker → `docker compose down && docker compose up --build`; обновить README/ARCHITECTURE/RESPONSE_FORMAT/TEST_CHECKLIST по правилам корневого `CLAUDE.md`.
6. **Процесс изменился** (новые правила, обязательные файлы/проверки) — обновить этот skill или корневой `CLAUDE.md`.
7. **Итог пользователю**: ревью по диффу, нужны ли миграции/пересборка, блок команд для ручного запуска, изменения контрактов API. Без `git commit`.
