# Нагрузочное тестирование (Locust)

Сценарии нагрузки на прод-API. Данные и токены готовит `scripts/issue_load_test_tokens.py` на сервере, Locust запускается с отдельной машины (Mac). Папка не попадает в Docker-образ (`.dockerignore`), зависимости — отдельные от бэкенда.

## Целевая нагрузка и критерии успеха

Ожидаемый пик первого года — около 5 RPS (2–2.5 тыс. DAU, 2–3 сессии в день, 5–8 запросов на сессию, вечерний пик и всплески ×3–5). **Целевая нагрузка — 50 RPS** (десятикратный запас). `MobileUser` ждёт 5–15 с между действиями, поэтому 500 виртуальных пользователей ≈ 50 RPS.

| Метрика | Порог на 50 RPS | При всплеске |
|---|---|---|
| Доля ошибок (5xx, таймауты, неожиданные статусы) | < 0.1% | < 1% |
| p95 обычных запросов | < 500 мс (GET — ориентир < 200 мс по Grafana) | возврат к фону ≤ 60 с после пика |
| p95 `/sync` с батчем 200–500 записей | < 2 с | — |
| Ответы 429 | 0 | 0 |
| CPU сервера | < 70% | — |
| RAM / своп | своп не растёт, нет OOM-kill и перезапусков воркеров | то же |
| Пул БД | нет `QueuePool limit … timed out` в логах | то же |
| Soak | p95 и память контейнера `api` стабильны 40 минут | — |

Доля ошибок, 429 и p95 по каждому эндпоинту проверяются автоматически в конце прогона: при нарушении Locust завершается с кодом 1 и печатает список нарушений. p95 проверяется только у эндпоинтов, по которым набралось не меньше 100 запросов. Пороги переопределяются переменными `LOADTEST_MAX_FAIL_RATIO`, `LOADTEST_P95_MS`, `LOADTEST_OFFLINE_P95_MS`; `run.sh` сам ставит `LOADTEST_MAX_FAIL_RATIO=0.01` для всплесков и `1` для стресса.

Латентность Locust включает сеть до сервера. Источник правды по серверу — дашборд **Load Testing** в Grafana: на одном экране API (RPS, статусы, p95/p99 по эндпоинтам, запросы в обработке), сервер (CPU, RAM, обмен со свопом, load, диск), контейнеры, PostgreSQL (соединения, idle in transaction, транзакции, блокировки), Redis; ошибки из логов — в свёрнутом разделе внизу. Верхняя сводка окрашена по порогам из таблицы выше: оранжевый — близко к границе, красный — критерий нарушен.

## Сценарии

| Сценарий | Пользователь | Вес |
|---|---|---|
| Первая страница транзакций с `If-None-Match`, иногда следующая страница | `MobileUser` | 25 |
| Бюджеты текущего месяца с `If-None-Match` | `MobileUser` | 20 |
| `/sync`: 5–20 операций и 0–2 бюджета | `MobileUser` | 30 |
| Создание операции | `MobileUser` | 15 |
| Курсы валют | `MobileUser` | 5 |
| Удаление созданной операции | `MobileUser` | 5 |
| `/sync`: 50–150 операций (клиент после работы без сети) | `OfflineSyncUser` | 0.5% пользователей |

AI-инсайты в нагрузку не входят: каждый запрос — платный вызов Gemini. Обновление токенов тоже: лимит `/auth/refresh` считается по IP, и с одной машины тест проверял бы только лимитер.

Профили (`LOADTEST_SHAPE`, файл `shapes.py`):

| Профиль | Что делает | Длительность |
|---|---|---|
| `steps` | 10 → 25 → 50 RPS по 5 минут | 15 мин |
| `soak` | 50 RPS | 40 мин |
| `spike` | фон 5 RPS → 50 RPS за 5 секунд на 3 минуты → фон | 8 мин |
| `double_spike` | два всплеска с паузой в минуту | 10 мин |
| `stress` | 50 → 100 → 150 → 200 → 300 RPS по 3 минуты | 15 мин |

## Токены и лимиты

Лимиты API считаются на пользователя (`/sync` — 60 в минуту, создание операции — 120 в минуту). Несколько виртуальных пользователей делят один токен: при 150 токенах запаса хватает до 3000 виртуальных пользователей (≈ 300 RPS, профиль `stress`). Для нагрузки выше — больше токенов (`--users 400`). Ответы 429 считаются нарушением: значит, токенов мало, а не сервер не справился.

Access-токены живут 60 минут (`ACCESS_TOKEN_EXPIRE_MINUTES`): токены выпускаются непосредственно перед прогоном, `soak` укладывается в этот срок. Серия прогонов дольше часа — с перевыпуском токенов (шаг 4); признак истёкших токенов — ошибки `HTTP 401` в выводе.

## Порядок прогона

### 1. Подготовка сервера

```bash
cd /opt/getbalanceai_api
# Алиас действует в текущей сессии shell; в новой сессии — объявить заново
alias dc='docker compose -f docker-compose.yml -f docker-compose.prod.yml'

./scripts/backup_db.sh
df -h / && free -m

# 150 пользователей с токенами (по 1000 операций за год) + 3000 фоновых (~1 млн операций), затем ANALYZE.
# Занимает несколько минут; повторный запуск без cleanup отказывает (код 1)
dc exec api python scripts/issue_load_test_tokens.py issue --users 150 --background-users 3000 --out /tmp/loadtest_tokens.json
dc cp api:/tmp/loadtest_tokens.json ./loadtest_tokens.json && dc exec api rm /tmp/loadtest_tokens.json
```

### 2. Mac: окружение и токены

```bash
cd getbalanceai_api
python3 -m venv loadtest/.venv && source loadtest/.venv/bin/activate
pip install -r loadtest/requirements.txt

scp <server>:/opt/getbalanceai_api/loadtest_tokens.json loadtest/ && ssh <server> rm /opt/getbalanceai_api/loadtest_tokens.json
cd loadtest
```

Файл токенов (`loadtest_tokens*.json`) в `.gitignore`; он даёт доступ к тестовым аккаунтам до cleanup.

### 3. Прогоны

Каждый сценарий запускается скриптом `run.sh` из папки `loadtest/` (venv подхватывается сам, `--host` по умолчанию — прод, другой — через переменную `HOST`):

```bash
./run.sh <сценарий> [дополнительные флаги locust]
```

| Сценарий | Что запускает | Длительность |
|---|---|---|
| `smoke` | 2 пользователя — все запросы должны быть успешными | 1 мин |
| `steps` | профиль `steps`, 4 процесса | 15 мин |
| `soak` | профиль `soak`, 4 процесса | 40 мин |
| `spike` / `double_spike` | всплески, допустимая доля ошибок 1% | 8 / 10 мин |
| `offline` | 50 `OfflineSyncUser` с батчами 200–500 записей (максимум схемы) | 5 мин |
| `cold_start` | `spike` сразу после перезапуска API (см. ниже) | 8 мин |
| `stress` | рост до 300 RPS; ошибки не считаются нарушением — ищем точку отказа | 15 мин |

**Вывод в терминале.** Каждые 2 секунды печатается таблица по эндпоинтам (запросы, ошибки, среднее/медиана/максимум, RPS), плюс события запуска пользователей и смены ступеней профиля. Ошибки запросов печатаются по ходу теста строкой `WARNING/loadtest: Ошибка <метод> <эндпоинт>: HTTP <код> (всего таких: N)` — первая ошибка каждого вида и затем каждая сотая. Если ответа не было, вместо кода — причина: `нет ответа: ConnectionTimeout(...)`, `ConnectionResetError(...)` и т. п. (таймаут клиента — 60 с). В конце — итоговая таблица с перцентилями, результат проверки критериев успеха и путь к отчёту. Ctrl+C останавливает тест досрочно, отчёт при этом сохраняется. На macOS `run.sh` запускает Locust через `caffeinate -dims`: Mac не засыпает до конца прогона (от закрытой крышки без внешнего питания и монитора это не защищает).

**Отчёты.** Каждый запуск создаёт свою папку `loadtest/reports/<дата_время>_<сценарий>/` (в `.gitignore`), повторные прогоны предыдущие не перезаписывают:

| Файл | Содержимое |
|---|---|
| `report.html` | графики RPS, времени ответа и числа пользователей по времени, таблицы перцентилей и ошибок — открыть в браузере |
| `console.log` | полный вывод терминала |
| `stats_stats.csv` | итог по эндпоинтам с перцентилями |
| `stats_stats_history.csv` | статистика по эндпоинтам каждые несколько секунд за весь прогон |
| `stats_failures.csv`, `stats_exceptions.csv` | ошибки по видам |

Код завершения `run.sh` — код Locust: `0` — критерии успеха выполнены (единичные ошибки в пределах допустимой доли не мешают), `1` — нарушены (список — в конце вывода).

Порядок прогонов:

```bash
./run.sh smoke
./run.sh steps
./run.sh soak
# Перед гидроударом — перевыпуск токенов (шаг 4): после smoke, steps и soak прошло больше часа
./run.sh spike
./run.sh double_spike
./run.sh offline
```

**Холодный старт после деплоя** — `spike` сразу после перезапуска API со сброшенным кэшем курсов (резервная копия `currency_rates:last_successful:USD` остаётся):

```bash
# На сервере
dc restart api && dc exec redis redis-cli DEL currency_rates:USD
dc ps api   # дождаться (healthy)
# Сразу после этого — на Mac
./run.sh cold_start
```
Проверка stampede: в логах API за время теста не больше одного запроса к API курсов на воркер (4 воркера gunicorn).

**Стресс до отказа** — вне рабочих часов (300+ RPS заметны в офисной сети):
```bash
./run.sh stress
```
Цель — найти ступень, на которой появляются ошибки, и узкое место (CPU воркеров, пул БД 4 × (5 + 10) = 60 соединений, RAM). Ступень с ошибками видна в `report.html` и `stats_stats_history.csv`.

Во время прогонов можно держать открытым дашборд **Load Testing** (`https://grafana.getbalanceai.app/d/load-testing`, обновление каждые 30 с, окно — последние 30 минут): обмен со свопом, соединения и idle in transaction Postgres, deadlock-и видны там же, отдельные окна с `vmstat` не нужны. **Раздел «Логи» во время прогона не раскрывать:** запросы к Loki просматривают регуляркой все логи за окно, и при каждом обновлении их стоимость растёт вместе с длительностью теста — в soak это съедало до 0.6 ядра из 2 и давало минутные провалы латентности. Логи смотрите после прогона. После прогона выставьте в Grafana интервал времени прогона и сохраните скриншот в папку отчёта — `report.html` показывает картину со стороны клиента.

### 4. Перевыпуск токенов посреди серии

```bash
# На сервере
dc exec api python scripts/issue_load_test_tokens.py cleanup
dc exec api python scripts/issue_load_test_tokens.py issue --users 150 --background-users 3000 --out /tmp/loadtest_tokens.json
dc cp api:/tmp/loadtest_tokens.json ./loadtest_tokens.json && dc exec api rm /tmp/loadtest_tokens.json

# На Mac, из loadtest/
scp <server>:/opt/getbalanceai_api/loadtest_tokens.json . && ssh <server> rm /opt/getbalanceai_api/loadtest_tokens.json
```

### 5. Очистка

```bash
# На сервере: каскадно удаляет всех пользователей loadtest+...@getbalanceai.test и их ключи в Redis, затем ANALYZE
dc exec api python scripts/issue_load_test_tokens.py cleanup
dc exec api python scripts/issue_load_test_tokens.py cleanup   # повторный запуск: «Удалено тестовых пользователей: 0»
df -h /
```
Ожидается `0` (email в базе зашифрован, поэтому проверка — тем же скриптом, а не `LIKE` в SQL). Освобождённое место Postgres переиспользует под новые строки после autovacuum, но операционной системе не отдаёт; вернуть его на диск (таблицы блокируются на время выполнения):
```bash
dc exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<< "VACUUM FULL transactions, budgets, tokens, users;"
```

```bash
# На Mac, из loadtest/
rm loadtest_tokens.json
```
